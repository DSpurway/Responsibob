Responsibob — Team Reference Guide
The Responsibob Skill & Mode
What they are, the difference between them, and how to use them in Bob

What Is Responsibob?

Responsibob is a framework — baked into Bob — for treating code energy efficiency as something measurable, certifiable, and improvable. It applies an EPC-style A–G rating (like an energy performance certificate for a building) to software, grounded in real source code evidence. The ratings are based on two independent things: the inherent energy cost of the programming language chosen, and how efficient the actual algorithms and patterns in the code are.

A B C D E F G

A = excellent / G = very poor — same scale as a home energy performance certificate, applied to code.

Two Artefacts — What Was Built

Artefact 1
The Skill

A set of instructions that Bob loads when it needs to do a Responsibob assessment. Think of it as a detailed procedure book — it tells Bob exactly how to rate code, which reference data to use, and how to structure a certificate. It works inside any mode.

Artefact 2
The Mode

A persistent persona that keeps energy efficiency front of mind throughout an entire task — not just when you ask for a certificate. Bob is always Responsibob: flagging language choices, spotting inefficiency as it reads code, and suggesting the lightest appropriate tool at every decision point.

How to Use — The Skill

The skill activates automatically when you use words like energy, efficiency, sustainability, carbon, green code, responsible computing, or EPC in any conversation. You can also activate it explicitly by saying: "Use the Responsibob skill."

Here are the things you can ask the skill to do:

Generate a certificate
"Can you give me a Responsibob EPC for this codebase?"
Review a language choice
"We're thinking of using Python for this — what's the energy angle?"
Spot inefficiency in code
"Is there anything inefficient in this RPG program from an energy perspective?"
Compare two approaches
"Which is more energy efficient — streaming the tokens or buffering the full response?"
Ongoing advisory
"As we build this, flag anything that looks like it'll be wasteful."
Infrastructure context
"We're on IBM Power — what does that mean for our energy baseline?"

What the skill contains:

Two files live at .bob/skills/responsibob/ in the team workspace. The skill procedure file (SKILL.md) is a 7-step process Bob follows: understand what is being assessed → look up language multipliers → assess algorithmic efficiency → combine the two axes → position on the Defra curve → check for Jevons' Paradox risk → produce the output. The reference data file (reference-data.md) holds all the numbers Bob uses — the language energy table, Defra curve, IBM Power hardware data, and Jevons' risk table — so Bob does not guess or reason them from scratch each time.

How to Use — The Mode

The Responsibob mode is available in Bob's mode picker. Select it at the start of a task when you want energy to be a first-class consideration throughout — not just retrospectively.

1
Open the mode picker in Bob

Look for the mode selector in the Bob interface (usually bottom-left of the chat panel). Click it to see available modes.

2
Select "Responsibob"

It appears in the list as Responsibob. Selecting it switches Bob into the energy-aware persona for the duration of the task.

3
Work normally — Bob will surface the energy angle

You don't have to keep asking. As Bob reads code or discusses design choices, it will note language tiers, flag inefficiency patterns, suggest lighter alternatives, and position things on the Defra curve. It will not be preachy — it surfaces the energy angle and moves on.

4
Ask for a certificate at any point

At any stage you can say "give me a Responsibob certificate for what we've built so far" and Bob will produce an A–G HTML certificate grounded in the actual code it has been working on.

What a Certificate Looks Like

Every certificate produced by the skill or mode follows the same structure, delivered as a shareable HTML file:

Two-axis model

Rates language (structural — how efficient is this programming language at the hardware level?) and algorithm (variable — is the code doing the least unnecessary work?) independently, then combines them.

A–G overall rating

A single current rating and a potential rating — what is achievable with specific named changes. Like an EPC: "Current: D. Potential: B."

Evidence-grounded findings

Every rating is backed by a specific file name and line number in the actual code. No estimates, no generalities — Bob reads the source and cites it.

Ordered improvements

The top improvements ranked by energy impact, each with the specific code change needed and the file it applies to.

Defra curve position

Where this work sits in the four-layer framework: Policy (100%) → Infrastructure (40%) → Code/Algorithm (20%) → AI model selection. Honest about what code efficiency can and cannot do.

Jevons' Paradox context

A nuanced, context-specific note on whether efficiency gains risk being consumed by increased usage — differentiated by type of system, not a blanket warning.

The Framework in Brief — Two Axes

Axis 1 — Language Multiplier

Structural. Fixed.

Based on the arXiv 2410.05460 study. C and RPG are near-identical at ~1× the baseline. TypeScript is ~21.5× more expensive. Python is ~76×. This cannot be changed without changing language — it is the floor, not the ceiling. It is honest context, not a reason to avoid a language if it is the right tool.

Axis 2 — Algorithmic Efficiency

Variable. Improvable.

How much unnecessary work does the code do? N+1 database queries, buffering a full AI response when streaming would do, compiling software from source on every deployment, verbose debug logging on every request — these are the patterns that move a rating from A to F. And they are all fixable.

The key insight: A perfectly efficient algorithm in a "bad" language can still beat a wasteful algorithm in a "good" language — when the compute volumes differ by orders of magnitude. The PassportEye example from our own codebase: a Python OCR function that runs in milliseconds beats a large C++ language model at 100–300× lower energy, despite Python being 76× more expensive per operation — because choosing the right algorithm eliminated 99%+ of the work. Algorithm first. Language second. Operations third.

Files to Share with the Team

These three files together are everything needed to install Responsibob into a Bob workspace:

── Skill files (copy to team workspace)
.bob/skills/responsibob/SKILL.md ← the procedure Bob follows
.bob/skills/responsibob/reference-data.md ← the reference numbers and tables

── Mode (append to custom_modes.yaml)
C:/Users/<username>/.bob/settings/custom_modes.yaml ← add the responsibob mode entry

The skill files go in .bob/skills/responsibob/ inside the shared workspace. The mode entry goes in each team member's personal custom_modes.yaml — this is a per-user Bob settings file. Share the responsibob YAML block from the bottom of the file and ask each person to append it to their own copy.
